02Type

One rule for all type (v1.5). Every text style is one of five voices at one of six sizes, generated from foundations/tokens.json. A component may place text, colour it and put a line beside it; it never sets a typeface, a size, a weight or capitals, and the build refuses one that does. The table below is generated from the same rows as the stylesheet, so the two cannot disagree. A heading style sits only on its own element, h1 to h4; there is no H5 or H6.

04Containment

Contain with colour and space, not outlines. Before reaching for any of these, check whether you are compensating for a proximity error — you usually are, and the fix is to move things rather than draw a line between them. Four weights of line and no others (v1.5): the hairline (1px), the table line (2px, under a header row), the rule (4px, a line that goes with text) and the callout line (8px, a line on a filled box, top or left).

Why this section exists

Every visual defect found in the 16 August review lived in the page furniture, not in the components — the mastheads, the frame that overrode a dark-ground specimen, the note text that fell below the size floor. The components were right the whole time. The page around them was hand-drawn each time, and nothing checked it.

The build now refuses if any folder contains its own stylesheet. There is one page builder, and it is the only place page furniture is decided.
