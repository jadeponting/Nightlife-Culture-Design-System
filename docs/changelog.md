# Changelog

## v1.0 — August 2026

First version of the system as an enforceable repo rather than a written guide.

**Added**
- `contracts/layouts.json` — twelve slide layouts with slot contracts, word limits, required
  elements, permitted grounds and vertical anchors.
- `contracts/rules.json` — global colour, grid, composition, typography, chart and footer rules.
- `system/slides.css` — the slide system, with the anchor rule enforced in CSS and a visible coral
  warning when `data-anchor` is missing.
- `tools/validate.py` — validator. Standard library only.
- `tools/contrast.py` — WCAG contrast checker.
- `templates/deck.html` — a twelve-slide reference deck that passes validation.
- `AGENTS.md` / `CLAUDE.md` — the contract for any AI agent working in this repo.
- `golden/` — reference renders.

**Decisions**
- The anchor is a **contract field, not a styling choice**. Authors do not pick it. Implicit
  top-anchoring was the single largest cause of weak slides in earlier attempts.
- Ground classes carry their own text, kicker and title colours, so the colour law cannot be
  forgotten by setting a colour by hand.
- `maxBlocks` must be at least the number of slots a layout declares — enforced by
  `--check-contracts`, after the first draft shipped three layouts that contradicted themselves.
- Plain HTML and CSS only. No framework, no build step, no second source of truth.

## v1.1 — 16 August 2026

The system stops being a set of styles and becomes a set of decisions.

**Added**
- `foundations/tokens.json` and `foundations/rules.json` — the single source for every value and
  every rule. Nothing downstream is hand-written.
- `checks/build.py` — generates `foundations/nightlife-culture.css` from those two files.
- `checks/validate.py` — fails the build on a broken Fixed rule.
- `checks/check_stamps.py` — every derived artefact records the digest of its sources and fails
  when they diverge, so a stale copy cannot pass as current (ch18).
- `components/library.body.html` + `components/build_library.py` — the component library, built in
  two forms: a linked form that cannot go stale, and a self-contained form for sending.
- `components/route.py` — **the router.** Content in, component out. Asks the decision stack in
  order, and can refuse.
- `docs/build_routing.py` → `docs/how-the-logic-works.html` — the routing explainer. Generated by
  running the router, so it cannot describe behaviour the system does not have.

**Decisions**
- Components are grouped by **the job they do**, not by what they look like — six families:
  structure, argument, containment, evidence, punctuation, reference. This is what lets the same
  set serve a deck, a web page, a dashboard and an evaluation report.
- **The edge treatment is the instruction.** Top rule, left rule, flyer outline, band and hairline
  each carry a fixed meaning (v1.4 §09), so a container is chosen by asking what the reader is
  being told to do — never by eye.
- **The router can stop.** Factual integrity sits above brand expression in the stack, so evidence
  that fails the comparability gate or a plausibility test never reaches a colour decision. Bad
  data is not quietly repaired; it is refused with a reason.
- **Typed capitals are normalised at the source**, including single shouted words and shift-key
  artefacts, and re-applied as a format — so the underlying string stays readable to search,
  copy-paste and a screen reader.
- Charts stack their rows below 30rem. A bar earns its place by encoding length from zero; a
  squeezed track still looks like a chart while no longer being readable as one.
- Every string replacement in a build script asserts that it matched, after one silently wrote a
  file and reported success.
